# AusCheckt Is

Find it here: [https://auschecktis.at/](https://auschecktis.at/)

A static site that shows which **Heurigen** (Austrian wine taverns / Buschenschanken) in
Stammersdorf, Vienna, are "ausg'steckt" (open) on a given day — with opening hours, a map,
and a day-by-day calendar. The site is a plain static build with no backend: JSON data files
are turned into SEO-optimized HTML by a Python generator and published to GitHub Pages.

## How it works

```
input/heurigen_list.json   master list of all Heurigen (label, website, map link, coordinates, comment)
        │
        ▼
data/<key>.json            per-Heuriger list of opening-hour events (title, start, end, url, mapLink, lat, lng)
        │
        ▼
build_static_site.py       reads input/ + data/, renders the static site
        │
        ▼
generated/                 final static site (index page, /day/YYYY-MM-DD.html pages, assets)
```

- `input/heurigen_list.json` is the source of truth for each Heuriger's metadata (name,
  website, page with opening hours, Google Maps link, coordinates, and a free-text
  `comment` field for local/expert knowledge that overrides what the website says).
- `data/<key>.json` holds the actual calendar entries (one JSON array of events per
  Heuriger, filename = the key from `heurigen_list.json`). `data/archive/` keeps
  superseded/past versions of these files.
- The data in `data/` is **not** scraped automatically — it's maintained by following the
  instructions in [`input/prompt.md`](input/prompt.md) (see "Updating opening-hours data"
  below).
- `input/austrian_public_holidays_2026.json` is the reference list of Austrian public
  holidays, since many Heurigen open on holidays even outside their normal schedule.
- `build_static_site.py` (class `HeurigenSiteGenerator`) is the generator actually used by
  `build.sh` / CI. It loads every `data/*.json` file, merges in the master metadata, and
  renders the index page, one page per day (`generated/day/YYYY-MM-DD.html`), the map,
  `sitemap.xml`, and copies static assets from `input/assets/`.
- `enhanced_site_generator.py` is an **unused prototype** (a scraper-based generator). It's
  not called from `build.sh` or the GitHub Actions workflow — leave it alone unless you're
  specifically reviving that approach.

## Project structure

```
input/
  heurigen_list.json               master metadata for every Heuriger
  austrian_public_holidays_2026.json
  prompt.md                        instructions for updating data/ (see below)
  assets/                          static assets copied verbatim into generated/ (CSS, icons, CNAME, favicons, fonts)
  qr_codes/                        QR flyer assets
data/

  archive/                         superseded event files
generated/                         build output (do not edit by hand — regenerated by build_static_site.py)

```

## Data schema

### `input/heurigen_list.json` entry

```json
"presshaus": {
    "label": "Presshaus",
    "website": "https://biohof-steindl.at/",
    "link_opening_hours_page": "https://biohof-steindl.at/?p=1281",
    "comment": "",
    "location": "https://maps.app.goo.gl/vNFmAdBddrLGkxpA7",
    "lat": 48.303258,
    "lng": 16.410771
}
```

- `presshaus` (the key) is the internal id, used as the filename for `data/<key>.json`.
- `label` → event `title`.
- `website` / `location` (Google Maps link) / `lat` / `lng` are copied onto every event.
- `link_opening_hours_page` is the **only** page that should be consulted for hours.
- `comment` may contain manually-curated corrections/exceptions — always take precedence
  over what's parsed from the website.

### `data/<key>.json` event

```json
{
  "title": "Presshaus",
  "start": "2025-01-17T16:00:00",
  "end": "2025-01-17T22:00:00",
  "url": "https://biohof-steindl.at/",
  "mapLink": "https://maps.app.goo.gl/vNFmAdBddrLGkxpA7",
  "lat": 48.303258,
  "lng": 16.410771
}
```

One JSON array per file, one object per opening-hours slot. `start`/`end` are local
Europe/Vienna datetimes.

## Updating opening-hours data

Opening hours are **not** scraped automatically (the CI step for that is disabled — see
`build-deploy.yml`). Instead, refresh a Heuriger's data by handing an LLM the instructions
in [`input/prompt.md`](input/prompt.md) together with the date range and Heuriger to check,
e.g.:

```
bitte lies den prompt und folge den Anweisungen für den Zeitraum {x} bis {y} für den Heurigen {z}.
```

Key rules from `input/prompt.md`:
- Only follow the URL in `link_opening_hours_page`; never guess.
- Read `comment` first — it can override/supplement the website.
- Missing end time or `00:00` → use `23:59`. Missing start time → use `18:00`.
- Don't fetch/parse PDFs directly — flag to the user if hours are only in a PDF.
- Match German month abbreviations (`Jän`, `März`, …) and cross-check public holidays
  against `input/austrian_public_holidays_2026.json`.
- Only future opening hours matter; drop anything in the past.
- If a page 404s or is unreachable, report an error instead of guessing.

### Special cases (Sonderfälle)

**Stöger** — not fully covered by `heurigen_list.json`/website, opening hours "1.5.–30.8. -
im Kalender, aber kenne ich nicht":

```json
"stoeger": {
    "label": "Stöger",
    "website": "http://www.stammersdorf.com/index.php/heurige/profil/49",
    "link_opening_hours_page": "",
    "comment": "1.5.-30.8. - im Kalender, aber kenne ich nicht",
    "location": "https://maps.app.goo.gl/6St9UPESJW3xWXnU7"
}
```

**Der Weingarten** — no 2025 schedule was published; website still showed 2024 info:

```json
"weingarten": {
    "label": "Der Weingarten",
    "website": "https://www.derweingarten.at/",
    "link_opening_hours_page": "https://www.derweingarten.at/",
    "comment": "",
    "location": "https://maps.app.goo.gl/mrD7zkUayFaa3BFn9"
}
```

**Dreh und Drink** — no explicit opening hours published for the year, weekends only.

## Build & deploy

### Build commands

```bash
# Full automated build
./build.sh

# Manual step
python3 build_static_site.py  # generates generated/ from input/ + data/
```

### Generated output
- `generated/index.html` — main overview page
- `generated/day/YYYY-MM-DD.html` — daily event pages
- Complete with structured data, maps, and SEO optimization

### Local development

```bash
./build.sh
cd generated && python3 -m http.server 8000
```

### Automation (GitHub Actions)

- Builds and deploys on pushes to `main` and on manual workflow dispatch
  (`.github/workflows/build-deploy.yml`).
- Deploys `generated/` to GitHub Pages under the custom domain `auschecktis.at`
  (see `input/assets/CNAME`).
- Commits `data/` and `input/` back to the repo if they changed during the build
  (the automatic scraping step itself is currently disabled in the workflow — data is
  updated manually as described above).

### Manual GitHub Pages deploy

`deploy.sh` builds the site and force-pushes `generated/` to the `gh-pages` branch. This is
an alternative to the GitHub Actions flow above.

## SEO features

### JSON-LD structured data
Each event includes complete Schema.org markup:
```json
{
  "@context": "https://schema.org",
  "@type": "Event",
  "name": "Presshaus - Ausg'steckt",
  "startDate": "2025-10-31T15:00:00",
  "location": {
    "@type": "Place",
    "geo": {
      "@type": "GeoCoordinates",
      "latitude": 48.303258,
      "longitude": 16.410771
    }
  }
}
```

### Microdata in HTML
```html
<div itemscope itemtype="https://schema.org/Event">
  <h4 itemprop="name">Presshaus</h4>
  <time itemprop="startDate" datetime="2025-10-31T15:00:00">
    ab 15:00 Uhr
  </time>
</div>
```
