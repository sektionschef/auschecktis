# AusCheckt Is

Find it here: [https://auschecktis.at/](https://auschecktis.at/)

A static site that shows which **Heurigen** (Austrian wine taverns / Buschenschanken) in
Stammersdorf, Vienna, are "ausg'steckt" (open) on a given day — with opening hours, a map,
and a day-by-day calendar. The site is a plain static build with no backend: JSON data files
are turned into SEO-optimized HTML by a Python generator and published to GitHub Pages.

## How it works

```
input/heurigen_list.json   master list of all Heurigen (label, website, map link, coordinates, comment)
        │
        ▼
data/<key>.json            per-Heuriger list of opening-hour events (title, start, end, url, mapLink, lat, lng)
        │
        ▼
build_static_site.py       reads input/ + data/, renders the static site
        │
        ▼
generated/                 final static site (index page, /day/YYYY-MM-DD.html pages, assets)
```

- `input/heurigen_list.json` is the source of truth for each Heuriger's metadata (name,
  website, page with opening hours, Google Maps link, coordinates, and a free-text
  `comment` field for local/expert knowledge that overrides what the website says).
- `data/<key>.json` holds the actual calendar entries (one JSON array of events per
  Heuriger, filename = the key from `heurigen_list.json`). `data/archive/` keeps
  superseded/past versions of these files.
- The data in `data/` is **not** scraped automatically — it's maintained by following the
  instructions in [`input/prompt.md`](input/prompt.md) (see "Updating opening-hours data"
  below).
- `input/austrian_public_holidays_<year>.json` (currently 2026 and 2027) is the reference
  list of Austrian public holidays, since many Heurigen open on holidays even outside their
  normal schedule. Add the next year's file before entering data for it.
- `build_static_site.py` (class `HeurigenSiteGenerator`) is the generator actually used by
  `build.sh` / CI. It loads every `data/*.json` file, merges in the master metadata, and
  renders the index page, one page per day (`generated/day/YYYY-MM-DD.html`, from today
  until the last event), the map, `sitemap.xml`, and copies static assets from
  `input/assets/`. Coordinates, Google Maps link and website URL always come from
  `heurigen_list.json`, overriding whatever is stored in the event files.
- The index page only embeds upcoming events and lets visitors browse day by day up to
  the last known opening day. Opening hours are shown as "14:00–22:00 Uhr", or as
  "ab 14:00 Uhr" when the end is unknown (stored as `23:59`).
- `validate_data.py` checks `heurigen_list.json` and all `data/*.json` files (valid JSON,
  required fields, title = label, end after start on the same day, no duplicates, a data
  file for every Heuriger). `build.sh` runs it first, so a broken file stops the deploy.

## Data schema

### `input/heurigen_list.json` entry

```json
"presshaus": {
    "label": "Presshaus",
    "website": "https://biohof-steindl.at/",
    "link_opening_hours_page": "https://biohof-steindl.at/?page_id=7",
    "comment": "",
    "location": "https://maps.app.goo.gl/vNFmAdBddrLGkxpA7",
    "lat": 48.303258,
    "lng": 16.410771
}
```

- `presshaus` (the key) is the internal id, used as the filename for `data/<key>.json`.
- `label` → event `title`.
- `website` / `location` (Google Maps link) / `lat` / `lng` are copied onto every event.
- `link_opening_hours_page` is the **only** page that should be consulted for hours. It is
  left empty when the hours are on the `website` itself — then use `website`.
- `comment` may contain manually-curated corrections/exceptions — always take precedence
  over what's parsed from the website.

### `data/<key>.json` event

```json
{
  "title": "Presshaus",
  "start": "2025-01-17T16:00:00",
  "end": "2025-01-17T22:00:00",
  "url": "https://biohof-steindl.at/",
  "mapLink": "https://maps.app.goo.gl/vNFmAdBddrLGkxpA7",
  "lat": 48.303258,
  "lng": 16.410771
}
```

One JSON array per file, one object per opening-hours slot. `start`/`end` are local
Europe/Vienna datetimes.

## Updating opening-hours data

Opening hours are **not** scraped automatically. Instead, refresh a Heuriger's data by handing an LLM the instructions
in [`input/prompt.md`](input/prompt.md) together with the date range and Heuriger to check,
e.g.:

```
bitte lies den prompt und folge den Anweisungen für den Zeitraum {x} bis {y} für den Heurigen {z}.
```

Key rules from `input/prompt.md`:
- Only follow the URL in `link_opening_hours_page`; never guess.
- Read `comment` first — it can override/supplement the website.
- Missing end time or `00:00` → use `23:59`. Missing start time → use `18:00`.
- Don't download/parse PDFs from the web — flag to the user if hours are only in a PDF.
  Local PDFs referenced in `comment` (e.g. Klager) are the authoritative source.
- Match German month abbreviations (`Jän`, `März`, …) and cross-check public holidays
  against `input/austrian_public_holidays_<year>.json`.
- Only future opening hours matter; only replace entries within the requested period.
- If a page 404s or is unreachable, or lists no dates for the period, report it instead of
  guessing.

### Known special cases

- **Reinbacher**, **Schreckenschlager** — no own website; dates come from their
  wienerwein.at profiles. Schreckenschlager says to ask by phone for exact dates.
- **Wieninger.next** — pop-up on single weekends; the dates are only on a poster image
  on the website.
- **Szüts/Suchel** — the website lists dates only up to the end of September, although it
  says "März bis Dezember". No later entries until new dates are published.
- **Zum Gustl** — the website only says "every weekend in good weather" without a season
  end.
- **Dornröschenkeller** — the own domain is offline; dates come from the wienerwein.at
  profile.
- Many Buschenschanken close at short notice in bad weather (Bartholomäus Hütte,
  Biohof N°5, Zum Gustl, Ausblick Wien). The site can't reflect that.

## Build & deploy

### Build commands

```bash
# Full build (validate data, then generate the site)
./build.sh

# Single steps
python3 validate_data.py      # check input/ + data/ for errors
python3 build_static_site.py  # generates generated/ from input/ + data/
```

### Generated output
- `generated/index.html` — main overview page
- `generated/day/YYYY-MM-DD.html` — daily event pages
- Complete with structured data, maps, and SEO optimization

### Local development

```bash
./build.sh
cd generated && python3 -m http.server 8000
```

### Automation (GitHub Actions)

- Builds and deploys on pushes to `main`, daily at 02:00 UTC (so past day pages drop out
  and the sitemap stays current), and on manual workflow dispatch
  (`.github/workflows/build-deploy.yml`).
- Deploys `generated/` to the `gh-pages` branch / GitHub Pages under the custom domain
  `auschecktis.at` (see `input/assets/CNAME`).
- `generated/` is not committed; CI always builds it from scratch.
- Note: GitHub disables scheduled workflows after 60 days without repository activity —
  re-enable it in the Actions tab if that happens.

## SEO features

### JSON-LD structured data
Each event includes complete Schema.org markup:
```json
{
  "@context": "https://schema.org",
  "@type": "Event",
  "name": "Presshaus - Ausg'steckt",
  "startDate": "2025-10-31T15:00:00",
  "location": {
    "@type": "Place",
    "geo": {
      "@type": "GeoCoordinates",
      "latitude": 48.303258,
      "longitude": 16.410771
    }
  }
}
```

### Microdata in HTML
```html
<div itemscope itemtype="https://schema.org/Event">
  <h4 itemprop="name">Presshaus</h4>
  <time itemprop="startDate" datetime="2025-10-31T15:00:00">
    ab 15:00 Uhr
  </time>
</div>
```
